## 判明した事実
- 30（ラベル）、300（プロンプト）、80（理由）、3（件数）は、上流の agent-status-panel（同じ選択肢を iPhone に出すアプリ）の規則に合わせたもの。`src/next-actions.mjs` の冒頭に「規則は agent-status-panel に合わせる」とあり、README にも同じ約束がある。数字の理由（ボタンの幅なのか、目安なのか）は、上流の README とコードのどちらにも書かれていない。
- 規則を満たさないカードは、上流も plugin も、ブロック全体ではなく 1 枚ずつ捨てる（`isSuggestion` で絞る）。理由（`reason`）だけは、規則を外れても切り詰めて残す。
- カードのラベルのスタイル（`panel/style.css`）は、折り返しの制限も省略表示も無く、長いラベルは折り返してカードが縦に伸びる。プロンプトは 3 行で切り、理由は切らない。
- 実機のパネルの幅は 349 CSS ピクセル（`orca plugin shot` の撮影、2026-11-22。幅はリーダーがサイドバーをどう広げているかで変わる）。実機のパネルは Windows の `Yu Gothic UI`（かなが比例幅で、13px で 1 文字が約 11px）で描画される。確かめ方: 同じ文字列の幅が、`Yu Gothic UI` の計測値（275.6px）と実機の撮影画像（約 276px）で一致した。
- 実機のフォント（`Segoe UI`、`Yu Gothic UI`）で、パネルと同じ CSS を使って、ラベルの長さごとの行数を測った（WSL 側の Chromium に Windows のフォントを使わせた。折り返しは、実機の撮影画像の目標、タスクの行数と一致することで較正した）。ラベルの行数（カード全体の高さ）:

  | 幅 | 日本語のラベル | 英数字の多いラベル |
  |---|---|---|
  | 349px（実機） | 23 文字まで 1 行（133px）、30〜60 文字は 2 行（153px） | 40 文字まで 1 行、50〜60 文字は 2 行 |
  | 280px（狭いとき） | 12 文字は 1 行、23〜40 文字は 2 行、50〜60 文字は 3 行（172px） | 30 文字まで 1 行、40〜60 文字は 2 行 |
  | 440px（広いとき） | 35 文字まで 1 行（99px）、40〜60 文字は 2 行（118px） | 50 文字まで 1 行、60 文字は 2 行 |

  1 行増えるごとにカードは約 20px 伸びる。カードの高さの大半は、理由（12px、折り返す）とプロンプト（最大 3 行）が占める。
- 結論: 30 文字は、パネルの幅から決まる値ではない。実機の幅（349px）で、日本語 60 文字までが 2 行に収まるので、上限を 40 や 60 にしても、パネルの表示は壊れない（1 行増えるだけ）。狭いとき（280px）は、40 文字までなら 2 行。
- 直近の回答 3 回でカードが出なかったのは、ラベルが 35、35、39 文字で、上限を超えたため（回答の `next` ブロックを plugin の解析に通して確認）。

## リーダーに決めてほしいこと
- ラベルの上限と守らせ方。Claude の案: 上限は 30 のまま、次の二つを足す。(1) plugin が、上限を超えたラベルを捨てずに 29 文字と「…」に切り詰める（理由が切り詰めで残るのと同じ。カードが消える失敗が、見た目だけの失敗に変わる）。(2) 全セッションの Stop フックで、上限を超えた `next` ブロックを検出して、書き直しを一度求める（上流の iPhone のアプリは、plugin の切り詰めが効かず、カードが消えるため）。理由: パネルの幅は上限の理由にならないが、上限を plugin だけで広げると、上流の規則とずれる（README の約束と、iPhone のアプリの動き）。トレードオフ: (1) は上流の規則からのずれが小さい代わりに、plugin の解析のコードを変える。(2) は常設のフックを全セッションに足す。別案: 上限を 40 に広げる（実機の幅で 2 行以内。エージェントへの指示文、README、テストを揃えて変える。iPhone のアプリでは 31 文字以上が消える）。答えで何が変わるか: 何もしなければ、長いラベルのカードは今後も黙って消える。
